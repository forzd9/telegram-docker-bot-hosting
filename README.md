## نبذة

مشروع بوت Telegram مكتوب بـPython لإدارة خدمة استضافة ملفات بوتات Python يرفعها المستخدمون. يتضمن المصدر مسارات لإدارة الملفات والطلبات والحسابات، وتشغيل الملفات في حاويات Docker، مع نظام نقاط ومتجر وخطط VIP. هذه أوصاف للوظائف الظاهرة في المصدر وليست تأكيدًا على اكتمالها أو عملها.

لا يحتوي المستودع على README حالي؛ لذلك لا توجد تعليمات سابقة أمكن التحقق منها أو الحفاظ عليها. كما أن وجود ملفات البناء والإعداد لا يثبت أن التطبيق قابل للتشغيل أو النشر.

## الوظائف الظاهرة في المصدر

- استقبال ملفات Python المرفوعة، تسجيلها ومراجعتها إداريًا، ثم إتاحة إجراءات مثل الموافقة أو الرفض والبدء والإيقاف والحذف وعرض السجلات.
- إنشاء حاويات Docker لإدارة تشغيل ملفات المستخدمين، مع مسارات ظاهرة لتثبيت اعتماديات الملفات ومراقبة حالة التشغيل.
- واجهة بوت للمستخدمين تتضمن الحساب والملفات والنقاط والهدايا اليومية والمتجر وطلبات الخطط أو VIP.
- أدوات إدارة ظاهرة في الشيفرة، تشمل مراجعة الملفات والطلبات، إدارة المستخدمين والحظر، إدارة القنوات، وبعض إعدادات الأسعار والخطط.
- عمليات خلفية ظاهرة تشمل الفوترة ومراقبة التخزين والتنظيف والنسخ الاحتياطي، إضافة إلى وظائف تشفير/فك تشفير وفحص سلامة ملفات. لم تُختبر هذه الآليات ولا ينبغي اعتبارها ضمانًا أمنيًا أو ضمانًا لاستعادة البيانات.

## بنية الملفات والإعدادات المتاحة

- `main.py`: نقطة الدخول الظاهرة، وتستخدم استطلاع Telegram (`infinity_polling`).
- `requirements (6).txt`: قائمة الاعتماديات المثبتة في وصف البناء. اسم الملف غير اعتيادي ويجب الحفاظ عليه كما هو أو توحيده مع Dockerfile عند تعديل المشروع.
- `Dockerfile`: يستخدم صورة Python 3.12 slim، ويثبت أدوات بناء وDocker واعتماديات Python، ثم يحدد `/start.sh` كنقطة بدء.
- `start.sh`: يحاول تشغيل Docker daemon داخل الحاوية، ينتظر مدة ثابتة، ثم يشغّل `main.py`.
- `fly.toml`: إعداد Fly يتضمن منطقة `lax`، ومسار تخزين دائم لـ`/app/user_data`، وخدمة HTTP داخلية على المنفذ `8500` مع `privileged = true`.

تظهر في ملفات المشروع أسماء إعدادات/ثوابت منها: `BOT_TOKEN`، `ADMIN_ID`، `BOT_USERNAME`، `CONTACT_USERNAME`، `BACKUP_CHANNEL`، `VIP_CHANNEL_ID`، `USER_DATA_DIR`، و`DOCKER_HOST`. هذه أسماء فقط؛ لا تضع رموزًا أو كلمات مرور أو معرّفات حساسة في هذا الملف أو في المستودع. يلزم نقل بيانات الاعتماد إلى مخزن أسرار مناسب والتحقق من طريقة قراءة كل إعداد فعليًا قبل النشر.

## متطلبات وإعداد

لا أورد أمر تشغيل عامًّا موصى به في هذه الوثيقة: سكربت البدء يحاول تشغيل Docker daemon داخل حاوية التطبيق، بينما إعداد Fly يطلب وضعًا مميزًا، كما يعرّف خدمة HTTP على المنفذ `8500` في حين أن نقطة الدخول الظاهرة تستخدم polling ولا يظهر في المصدر خادم HTTP واضح. يجب حسم هذا التعارض وتصميم عزل آمن قبل توثيق تشغيل أو نشر قابل للاعتماد. أي إعداد أو بناء أو تشغيل مذكور هنا **غير مجرّب**.
